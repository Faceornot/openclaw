# 2026-03-31

- 修复了 OpenClaw 本地 memory_search 不可用的问题，并最终恢复为真正的本地 embedding 路线。
- 初始现象：QMD / node-llama-cpp 在尝试 Vulkan 时失败；即使显式设置 `GGML_VULKAN=0`，仍会在 `Gathering information` 阶段卡很久。
- 进一步排查确认：`NODE_LLAMA_CPP_GPU=false` 可以避免 Vulkan 编译探测，但 QMD 仍会在本地 embedding 模型准备阶段尝试联网下载，且到 `huggingface.co:443` 的 TCP 连接失败。
- 实测网络结论：`huggingface.co:443` 不通，但 `hf-mirror.com:443` 可通，因此根因是 HuggingFace 官方下载链路不通，而不是机器完全断网。
- 一度将 `memory.backend = "qmd"` 去掉以绕开 QMD，验证到内置 memorySearch 的远程 provider 也不可用：`openai embeddings failed: 503` / `No available providers`。这一步帮助确认远程 provider 不是最终解法。
- 最终采取的稳定修复方案：从 `hf-mirror.com` 手动下载本地 GGUF embedding 模型 `embeddinggemma-300m-qat-Q8_0.gguf` 到 `/home/lenovo/.openclaw/models/embeddinggemma-300m-qat-Q8_0.gguf`。
- 之后将 `~/.openclaw/openclaw.json` 中的 `agents.defaults.memorySearch` 改为真本地配置：
  - `provider = "local"`
  - `fallback = "none"`
  - `local.modelPath = "/home/lenovo/.openclaw/models/embeddinggemma-300m-qat-Q8_0.gguf"`
- 重启 gateway 后实测成功：`memory_search` 返回 `provider: local`、`model: /home/lenovo/.openclaw/models/embeddinggemma-300m-qat-Q8_0.gguf`、`mode: hybrid`，且已能搜到 `MEMORY.md` 与 `memory/*.md` 的真实内容。
- 本次修复的关键经验：
  1. 不要继续纠缠 Vulkan；
  2. QMD/本地 embedding 首次使用时若依赖自动下载，网络会成为真正阻塞点；
  3. 在 HuggingFace 官方域名不通、镜像可通时，最稳方案是先手动下载 GGUF 到本地，再把 OpenClaw 指向本地 `modelPath`。
